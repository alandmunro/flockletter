# Staging private schema preparation

The staging migration role may create objects in its assigned schemas and has no database CREATE privilege. Customer workflows add exactly two private schemas: `flockletter_customer_jobs` and `flockletter_retention_control`. The database owner prepares the namespaces under its own ownership and grants schema USAGE/CREATE with grant option to the existing `flockletter_staging_migrator` before migrations 019/021. Existing namespaces may belong to the database owner or exact migration role. Other owners cause a refusal rather than an ownership change. Migration-created tables and functions belong to the migration role.

`node scripts/prepare-customer-schemas.mjs` reads one protected JSON line from standard input with `adminUrl` pointing to the exact `flockletter_staging` database and `expectedDatabase` equal to `flockletter_staging`. Never put connection strings or passwords in arguments, Git or chat. The helper verifies database/role ownership markers and the migration role’s restricted attributes. The selected administrator must be the exact target database owner. No SET authority or new role membership is required. The helper does not issue roles, alter role memberships, change passwords, grant database CREATE or access any other database.

The preparation transaction validates both namespace owners, creates only missing reviewed namespaces under the database owner, revokes PUBLIC access and grants the exact migration role USAGE/CREATE with grant option. It returns only completion flags. For existing migrator-owned namespaces, the helper verifies effective migration authority and the absence of PUBLIC grants without changing their owner or grants. A retry is safe. Static refusal codes distinguish missing owner authority, marker drift and namespace ownership drift without disclosing SQL, input or secrets. Newly provisioning staging calls the same helper before migrations. An existing staging installation runs it once in its protected owner release context, followed by the ordinary migration release.

The migrations skip namespace creation when the reviewed schema is already present. If a missing namespace requires authority the migrator does not possess, they stop with an instruction to use the owner preparation step. Runtime grants remain confined to the reviewed public tables and six fixed scheduler functions; runtime and migrator retain no database CREATE privilege.

Disposable tests cover non-superuser provisioning/replay, owner-created private namespaces with migration-owned tables/functions, owner/role/database marker refusals, runtime denial of database CREATE and underlying scheduler-table access, scope-checked scheduler functions and secret-free CLI output. Hosted execution is separate and has not been performed by this test suite.
