# Sender infrastructure onboarding

D-042 extends FL-OPS-003/005/007, FL-ID-005 and FL-API-001/003 with durable customer sender infrastructure plans. The normal owner UI, HTTP and MCP use the same commands. Runtime credentials cannot bypass tenant policies or call arbitrary cloud operations supplied by a browser.

Save the business sender profile on Delivery first. Infrastructure reviews its exact revision, from address, derived public domain, legal identity, provider binding and verified billing source. A changed profile, source or provider needs a new review. A review does not provision resources. The owner must approve that exact digest before the job is queued. One pending plan per brand and five per workspace bound concurrent work.

Capture mode is available only outside production. Its durable plan, approval, processing, cancellation, state, audit and provider-route records use the actual controller. The result is explicitly captured and unverified. Its DNS names and values end in `.invalid`; its resource references are capture placeholders. It can never be returned by the verified delivery-route or trusted feedback-route methods.

AWS mode requires a dedicated operator-configured adapter and an independently reserved provisioning allowance. The controller calls `budgetPermit(sql, request)` under the workspace lock, then commits the named attempt before making the external call. The default is denial. The server fixes the account, US region, resource prefix and callback; customer input contains no resource ARN, account, region, credential, destination or callback field. Each apply is one named step: tenant, configuration, identity, topic, topic policy, identity association, configuration association, event destination or subscription. After the durable claim commits, a new workspace lock rechecks the exact claim revision, original owner, current profile, billing, cancellation and erasure checkpoint immediately before handoff. The lock remains held for the bounded provider apply. The trusted provider receives a domain-proof callback on the same SQL connection, which avoids nested pool loans while preserving current ownership verification.

A lost acknowledgement stays uncertain. Processing that step again performs inspection only. It advances only when authoritative inspection observes completion; it never speculatively resubmits an unknown step. An adapter rejection is permitted only for a pre-mutation guard failure or proven nonacceptance; that named step can be held and explicitly retried after its cause is fixed. All SDK mutation errors and failed post-write observations remain unknown. Attempts are bounded. Cancellation stops future steps, preserves resource/unknown evidence and disables its delivery route; it does not claim that already-created resources were deleted.

Provider facts are schema checked and bound to the exact operation, domain and from address. Public DNS records and observed resource identifiers are retained behind tenant policies. Only observed topic and topic-policy completion can register an AWS feedback candidate. Feedback registration does not authorize sending. A signed SNS subscription confirmation additionally requires the exact still-authorized route and subscription step; capture, cancellation, erasure, owner loss and changed sender/service facts deny confirmation. Historical delivery feedback retains its separate reconciliation path. Delivery readiness separately requires a freshly inspected, fully verified AWS route, the exact current sender/profile/source, current authority, domain ownership, sender checks and all ordinary campaign safeguards. Capture data and caller-supplied ARNs cannot satisfy those conditions.

`customer_infrastructure_intents` and immutable `customer_infrastructure_events` use forced workspace policies. `customer_provider_routes` uses forced brand policies and scoped foreign keys. The runtime receives SELECT/INSERT/UPDATE for intents/routes and SELECT/INSERT for events, with no DELETE grants. All three stores are included in retention inventory and the populated all-table erasure/restore fixture. Private budget metadata and operator activation remain separate protected controls.

The local model drafted the InfrastructureSetup screen (108.63 seconds, 7,922 output characters). Chat corrected a nonexistent profile field, brand-switch state handling, unknown-outcome reconciliation, safe held-job retry visibility, long-value wrapping and misleading external-action wording. Chat retained the controller, security contracts, budget/authority decisions, typed provider boundary, lifecycle tests and integration review. No AWS resources or hosted sender settings were changed during this work.

Verification: fourteen controller cases cover durable capture, strict input/tenant boundaries, budget-before-network, unknown lookup without resend, pending limits, source/authority changes, cancellation races, exact idempotent process replay, and queued profile/cancel/erasure changes before provider handoff. SNS confirmation cases reject capture, altered route, cancellation and erasure. The complete normal browser proof also saves the legal profile and performs Infrastructure review, approval and capture through Operations, verifying `.invalid` DNS and an unverified route. The full retirement-history and infrastructure inventory remains populated in the erasure/restore fixture.
