# Campaign feedback on staging

In **Campaigns**, choose **Local feedback test** for an offline rehearsal. Review the current campaign revision, audience and time, then approve the displayed test. **Amazon SES mailbox simulator** is a separate method that can contact AWS. Earlier approvals retain their original method. The dashboard and MCP use the same brand-specific choices (`rehearsal_methods`) and the same review, approval and report commands. [Rehearsal workflow](CAMPAIGN_PILOT.md)

| Flockletter test address | Local feedback result | Destination for an approved SES simulator test |
| --- | --- | --- |
| `reader@campaign.test` (fixed test mailbox) | Delivery | `success@simulator.amazonses.com` |
| `bounce@delivery.test` | Permanent bounce | `bounce@simulator.amazonses.com` |
| `complaint@delivery.test` | Complaint | `complaint@simulator.amazonses.com` |
| `delay@delivery.test` | Temporary bounce | Local testing only |

For an API or MCP connection, explicitly grant `campaign:simulate` together with `read` and `campaign:rehearse` before running either new method. Existing tokens cannot acquire these permissions from a deployment. For a group audience the connection also needs `audience:summary`.

To exercise multiple outcomes, use a group of confirmed synthetic contacts in the same brand. Open **Show recipient outcomes**, or read `rehearsal_outcomes` with the brand and rehearsal IDs. An accepted submission records provider acceptance. Its separate feedback field appears when an event matches the original attempt. A permanent bounce or complaint suppresses the matching subscriber in that brand. A temporary bounce records the difficulty. Later delivery events, replays and events for a different recipient cannot reverse suppression. After an uncertain AWS submission, the worker looks up the receipt for that operation. A missing receipt keeps the outcome unresolved.

## Optional AWS simulator setup

1. Set `APP_ENV=staging` and bind the worker to the intended workspace and brand. Set `FLOCKLETTER_SES_SIMULATOR_BINDING` to a server-side JSON object containing `workspaceId`, `brandId`, `region`, `accountId`, `tenant`, `configurationSet`, `from`, `identityArn` and `topicArn`. The identity and topic must match the configured US region and account. Verify the sending identity in SES, associate the identity and configuration set with the intended tenant, and verify the matching sender domain in Flockletter’s **Workspace**. Flockletter requires a successful ownership check within the previous 24 hours for both review and submission.
2. Supply `FLOCKLETTER_SES_ACCESS_KEY_ID`, `FLOCKLETTER_SES_SECRET_ACCESS_KEY` and, for temporary credentials, `FLOCKLETTER_SES_SESSION_TOKEN` through protected staging settings. Give this dedicated principal `ses:SendEmail` for the approved identity and configuration set only. Restrict the sender address and tenant with `ses:FromAddress` and `ses:TenantName`, and restrict every `ses:Recipients` value to the three exact AWS addresses above. The adapter disables open and click tracking on each request. Allow `ses:ApplyTrackingConfigurationOverrides` on `*` with both tracking condition keys constrained to `DISABLED`. [SES permissions](https://docs.aws.amazon.com/service-authorization/latest/reference/list_sesv2.html) · [Tracking override permissions](https://docs.aws.amazon.com/ses/latest/dg/configuration-overrides.html)
3. Configure the SES configuration set to publish delivery, bounce and complaint events to the dedicated standard SNS topic. Give only the SES service principal permission to publish on that topic, constrained by `AWS:SourceAccount` and the exact configuration-set `AWS:SourceArn`. Set the topic’s `SignatureVersion` to `2` (RSA-SHA256) and subscribe the HTTPS staging route `/api/v1/campaign-feedback/ses` using signed SNS envelopes. Flockletter verifies the topic, signature, account, sender identity, configuration set, tenant tag, operation and mapped destination before applying feedback. [SNS topic policy](https://docs.aws.amazon.com/ses/latest/dg/event-publishing-add-event-destination-sns.html) · [SNS signature configuration](https://docs.aws.amazon.com/sns/latest/dg/sns-verify-signature-of-message-configure-message-signature.html)

Review freezes a fingerprint of the workspace, brand and complete AWS route. A changed route requires a fresh review. To stop new AWS submissions while resolving previous receipts, remove the sending credentials and retain the original binding and notification endpoint. AWS bills simulator submissions like other SES mail. Follow the existing approval rule for each expense above $25. [AWS mailbox simulator](https://docs.aws.amazon.com/ses/latest/dg/send-an-email-from-console.html) · [D-031](../DECISIONS.md)

## Verification boundary

The offline feedback scenarios exercise Flockletter’s worker, database and reports. The direct SES SDK contract uses a substituted transport. The isolated Listmonk exercise compares its real `/api/tx` callback with the approved envelope, restores the original plain text and inline photos, and serializes that message with the real SES SDK into an in-memory transport. D-039 adds a private Listmonk rehearsal for the bound staging brand. Customer delivery still requires an observed AWS simulator run and an end-to-end check of the production route. O-002 governs production provider selection. [SES contract tests](../../tests/ses-simulator.test.ts) · [Listmonk exercise](LISTMONK_CAPTURE.md) · [Private Listmonk operation](PRIVATE_LISTMONK.md)

Hosted staging was verified on the free web instance after PR #15. The saved Alpine Field Notes test campaign, version 2, completed with one synthetic recipient and one attempt. Its dashboard displayed provider acceptance and a separate confirmed delivery; the AWS method was unavailable. Both staging readiness checks returned no gaps and external sending disabled. No real inbox or AWS account participated in this hosted rehearsal.
